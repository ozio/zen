# Встроенный MCP

Пункт 9 реализован и установлен на macOS ARM64. Текущая сборка `a9a0da176b9ad3377cb281ce138d7cc5e0efe297` добавляет настройку Codex/Claude Code и установку скиллов из браузера. Проверки текущего пакета и сохранённые результаты первоначальной реализации MCP, включая Inspector и стресс 1500 вкладок, разделены в [отчёте валидации](mcp-validation.md).

Zen содержит локальный MCP-сервер в родительском процессе браузера. Он запускается обычным способом, без Marionette, Remote Agent, порта DevTools или отдельного Node/Python-сервера. По умолчанию MCP выключен.

После включения галки сервер запускается вместе с этим профилем Zen и останавливается при снятии галки или выходе из браузера. Установка подключения агента или скилла сама сервер не включает.

В настройках откройте **MCP**, включите сервер и создайте именованный доступ. Панель показывает адрес, состояние, порт и выданные доступы. Основной профиль использует `http://127.0.0.1:3923/mcp`, независимый Playground — `http://127.0.0.1:3924/mcp`. Пустое поле порта возвращает соответствующее значение по умолчанию. Если порт занят, измените его в этой же панели.

Каждому клиенту выдаётся отдельный случайный bearer-токен. В профиле сохраняется только SHA-256 токена и метаданные клиента в `zen-mcp-clients.json`. Токен и готовую конфигурацию можно скопировать при создании или замене доступа; после ухода из панели они стираются из её полей. Для повторного получения замените токен. Отзыв и замена прекращают старые сессии/подписки и освобождают наблюдателей. Настройка включения и доступы переживают обычный перезапуск того же профиля. Доступы двух профилей не переносятся автоматически.

Клиент подключается через **Streamable HTTP** с заголовком `Authorization: Bearer TOKEN`. Пример для Codex (реальные значения скопируйте из панели):

```toml
[mcp_servers.zen]
url = "http://127.0.0.1:3923/mcp"

[mcp_servers.zen.http_headers]
Authorization = "Bearer TOKEN"
```

## Настройка Codex и Claude Code

В **Настройки → MCP → Подключение агентов** доступны отдельные кнопки **Настроить MCP для Codex** и **Настроить MCP для Claude Code**. Они создают независимый именованный доступ и сохраняют HTTP-подключение с токеном в конфигурации клиента: `~/.codex/config.toml` и `~/.claude.json`. Для Codex требуется установленный CLI; на macOS подходит также CLI, встроенный в приложение Codex/ChatGPT. Поддерживаются унаследованные браузером `CODEX_HOME` и `CLAUDE_CONFIG_DIR`.

Повторная настройка заменяет только ранее установленное этим профилем Zen подключение и отзывает его предыдущий токен. Остальные настройки и MCP-серверы сохраняются. Перед изменением конфигурации создаётся приватная резервная копия рядом с ней; новые файлы с токенами имеют права `0600`. Чужое подключение с таким же именем или изменённый блок Zen автоматически не перезаписывается. В этом случае используйте ручную настройку. Для Playground имя сервера — `zen_playground`, для основного Zen — `zen`.

Для ручного подключения создайте клиент в разделе **Доверенные клиенты**. Одноразовая панель содержит endpoint, токен, JSON, Codex TOML и кнопки копирования команд терминала. Примеры с условным токеном:

```sh
export ZEN_MCP_TOKEN='TOKEN'
codex mcp add zen --url 'http://127.0.0.1:3923/mcp' --bearer-token-env-var ZEN_MCP_TOKEN

claude mcp add --transport http --scope user zen 'http://127.0.0.1:3923/mcp' --header 'Authorization: Bearer TOKEN'
```

Переменная Codex действует в текущем терминале. Для приложения или постоянного подключения используйте кнопку настройки либо TOML с `http_headers`. После изменения конфигурации перезапустите агент. HTTP-параметры Codex описаны в [официальной документации](https://learn.chatgpt.com/docs/extend/mcp#streamable-http-servers), команды Claude Code — в [его руководстве MCP](https://code.claude.com/docs/en/mcp).

Кнопки **Установить скилл для Codex** и **Установить скилл для Claude Code** устанавливают короткие инструкции `zen-browser` в `~/.agents/skills/zen-browser/SKILL.md` и `~/.claude/skills/zen-browser/SKILL.md`. Для Playground создаётся отдельный `zen-playground`. Скилл описывает выбор экземпляра и явных целей, одноразовые снимки, проверку фактического результата, сохранение остальных вкладок и границу системного JS. Токенов в скилле нет. Изменённый пользователем или чужой скилл сохраняется; обновляются только совпадающие с записью предыдущей установки файлы. Codex использует [пользовательскую папку `.agents/skills`](https://developers.openai.com/codex/skills#where-to-save-skills), Claude Code — [`.claude/skills`](https://code.claude.com/docs/en/skills#where-skills-live).

**Открыть скиллы Codex** вызывает официальный `codex://skills`. Он открывает список скиллов; в [документированном списке deep links](https://learn.chatgpt.com/docs/reference/commands#deep-links) отдельной ссылки установки произвольного скилла нет. Поэтому установка выполняется локальной кнопкой Zen. Облачные Claude/Codex не могут обращаться к loopback этого Mac; эти настройки относятся к локальным клиентам.

Сервер слушает только числовой IPv4 loopback `127.0.0.1`. `Host` должен совпадать с адресом и портом сервера. Если запрос содержит `Origin`, допустим только собственный `http://127.0.0.1:PORT`. Внешние сайты не получают CORS-доступ. Перенаправление этого интерфейса наружу не является предусмотренным способом подключения.

## Граница выданного доверия

После выдачи доступа MCP не спрашивает дополнительного подтверждения перед каждой командой. Этот клиент может читать и изменять обычные вкладки, браузерный интерфейс и данные профиля. Инструмент `zen_javascript` в режиме `browser` выполняет **неограниченный JavaScript с системными привилегиями** в явно выбранном окне.

Обычные инструменты не перечисляют приватные окна и не предоставляют отдельной команды сохранённых паролей. Это не изоляция от доверенного клиента: системный JavaScript технически может обращаться и к приватным данным, и к хранилищу паролей. Доступ выдавайте клиенту с учётом этой границы. Таймаут ограничивает ожидание ответа; он не способен прервать произвольный синхронный JavaScript.

Системный JS использует отдельный контекст для пары клиент/окно; объекты и callbacks сохраняются между командами. Контекст освобождается при отключении клиента, отзыве доступа, закрытии окна или остановке сервера. Лимит — 32 окна на клиента. Для продолжительной работы держите подписку открытой: клиент без потоков и запросов освобождается после 30 секунд простоя. Освобождение контекста не отменяет уже сделанные изменения данных и интерфейса.

## Протокол

Поддерживаются четыре версии:

| Версия | Подключение и события |
|---|---|
| `2026-07-28` | Метаданные клиента и версии в каждом запросе; `server/discover`; `subscriptions/listen` через POST SSE. Без handshake и протокольной сессии. |
| `2025-11-25` | `initialize`, `notifications/initialized`, `Mcp-Session-Id`; GET SSE, подписки ресурсов, DELETE сессии. |
| `2025-06-18` | Та же схема прежней инициализации и сессий. |
| `2025-03-26` | Прежние сессии; также запросы JSON-RPC batch с ответами через SSE. |

Современная версия проверяет обязательные заголовки `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name` и их совпадение с телом. Кодировка sentinel Base64 для `Mcp-Name` декодируется перед сравнением. Неподдерживаемая версия возвращает `-32022`, несогласованные заголовки — `-32020`. Современный клиент передаёт в `params._meta` ключи `io.modelcontextprotocol/protocolVersion`, `io.modelcontextprotocol/clientInfo`, `io.modelcontextprotocol/clientCapabilities`. Старые клиенты сначала выполняют handshake.

Одноразовые ответы возвращаются JSON. Долгие подписки возвращаются `text/event-stream`. Клиент POST указывает `Accept: application/json, text/event-stream`. Для продолжительного сбора консоли/сети держите SSE-подписку открытой. Закрытие последнего потока клиента освобождает его наблюдателей; завершив работу, используйте `zen_client_disconnect` или удалите прежнюю протокольную сессию. Выданный доступ при этом сохраняется. Прежние неактивные сессии без потоков истекают через 30 минут. Возобновление по `Last-Event-ID` не предлагается.

Спецификация: [совместимость версий](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning), [Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http), [подписки](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/subscriptions).

## Явные цели и результаты

Начните с `zen_browser_state`. Он возвращает `instanceId`, сборку, окна, активные цели и имена возможностей. Для остальных инструментов передавайте этот `instanceId`. Окна и вкладки имеют собственные непрозрачные ID; фреймы и документы возвращают фактические идентификаторы Gecko. После перезапуска браузера или сервера перечитайте состояние: прежняя идентичность недействительна.

Команда не выбирает произвольное активное окно. При закрытии цели она возвращает ошибку. Мутации выполняются последовательно, чтения могут идти одновременно. После действия возвращается наблюдённое состояние. При ошибке сервер не повторяет действие автоматически; перечитайте состояние, прежде чем решать, нужен ли повтор.

Для DOM и браузерного интерфейса получите свежий снимок. В нём есть `snapshotId`, `elementId`, `documentId`. Снимок привязан к клиенту, цели и документу, действует 30 секунд и расходуется одним действием. Навигация, замена документа, удаление или перепрофилирование элемента делают его недействительным. Iframe инспектируется через его явный `frameId`; открытые shadow roots обходятся в снимке документа.

Списки возвращают `items`, `total` и необязательный `nextCursor`. По умолчанию — 100 элементов, допустимый размер страницы — 1–500. Список вкладок включает неактивные Spaces и не загружает выгруженные браузеры. DevTools через локальный `connectPipe` подключается только к явно запрошенным вкладкам.

Подробности сетевого запроса включают заголовки и, при запросе, доступное захваченное тело. Ограничения самого Gecko на доступность тела и подписанные расширения остаются в силе.

## Ресурсы и журнал

`resources/list` возвращает `zen://INSTANCE/state`, `/events`, `/capabilities`. Шаблон `zen://INSTANCE/tabs/{tabId}` читает минимальное состояние явной вкладки без её загрузки. На изменения браузера отправляются уведомления ресурсов; современная подписка получает только запрошенные виды уведомлений. События содержат последовательность, время, вид изменения и непрозрачные ID, без содержимого страниц.

В профиле ведётся ограниченный `zen-mcp-audit.jsonl`: метод, идентификаторы цели, результат и длительность. Аргументы, скрипты, страницы, пароли и bearer-токены в журнал не записываются. Профили, журналы, реальные токены и локальные доказательства не коммитятся.

## Разработка и проверка

Канонические исходники находятся в `src/zen/mcp/`; preference definitions — в `prefs/zen/mcp.yaml`. Модули и акторы регистрируются через `moz.build` и `ZenActorsManager`. Панель настроек добавлена патчами Firefox и локализациями en-US/ru. Новый код требует свежего import и полной сборки.

Контрактные проверки:

```sh
.zen-local/toolchains/node/bin/node --test tests/mcp/*.test.mjs
```

Они проверяют границы протокола, сессии, подписки, хеши/отзыв, схемы, очередь мутаций, принадлежность элементов/целей, ленивую пагинацию и жизненный цикл панели. Они не заменяют реальные операции на подписанном пакете, подключение MCP Inspector, сохранение того же профиля, стресс 1500 вкладок и действующие compatibility gates. Проверенный SHA, платформа, выполненные операции и оставшиеся ограничения записываются отдельно в отчёте валидации.
