# MCP: сайдбар, медиа и инструменты сайта

Наличие команд определяется `zen_browser_state.capabilities` конкретной сборки. Старые команды сохраняют совместимость. Агентские инструкции поставляются в [zen-browser skill](../src/zen/mcp/skills/zen-browser/SKILL.md). Каждая команда получает актуальный `instanceId`; операции сайдбара — также `windowId`.

## Выборка

`zen_sidebar_snapshot` возвращает Spaces, дерево папок/групп и страницы компактных дескрипторов вкладок без загрузки выгруженных страниц. `zen_tabs_query` принимает `tabIds`, `selectionId` или `filter`, а также дополнительный `filterLambda`. Ответ: `items`, `total`, `revision`, `selectionId`, `nextCursor`. Выборка охватывает все совпадения, даже при ограничении ответа `limit`; ID принадлежит клиенту и действует пять минут.

| Условие | Поля |
|---|---|
| Точные ID | `spaceId`, `spaceIds`, `groupId`, `containerId`, `containerIds`, `tabIds` |
| Папка | `folderId`, `recursive` (по умолчанию `true`) |
| Текст | `domain`, `registrableDomain`, `url`, `title`, `savedUrl` |
| Состояние | `selected`, `loaded`, `pending`, `discarded`, `pinned`, `essential`, `muted`, `hidden`, `playing`, `audible`, `pictureInPicture`, `pinChanged` |
| Композиция | `all`, `any`, `not` |
| Дубликаты | `duplicates:true` либо `{keep:"first"|"last"|"all",ignoreHash,ignoreParams,acrossContainers}` |

Строковый текстовый фильтр означает подстроку без учёта регистра. Объект выбирает один из `equals`, `contains`, `glob`, `regex` и необязательный `caseSensitive`. `domains` — массив точных имён хостов. Дубликаты по умолчанию учитывают контейнер; `keep:"first"` выбирает лишние копии, оставляя первую.

Например, незакреплённые GitHub-вкладки в Space, кроме активной и играющих:

```json
{"spaceId":"<space>","domains":["github.com"],"pinned":false,"essential":false,"selected":false,"playing":false}
```

## План, применение и Undo

`zen_tabs_plan` строит предпросмотр `move`, `sort`, `close`, `discard`, `reopen`, `open` или `pin`. `zen_tabs_apply({planId})` применяет его один раз, возвращая `operationId`, исход каждой вкладки, сводку и возможность Undo. Проверяется порядок/связи и состояние исходных окон: при конфликте нужен новый план. Повторный apply того же ID возвращает сохранённый результат, пока он доступен.

Сортировка: `sort:{by:"domain-title"|"title"|"last-used"|"url"|"index",direction:"asc"|"desc"}` либо массив полей/направлений. Числа в названиях сравниваются естественным образом; равные ключи сохраняют порядок. `lastAccessed` использует реальные данные браузера, `createdAt` может быть `null`.

```js
filterLambda: "t => !t.pinned && !t.playing"
sortKeyLambda: "t => [t.registrableDomain, t.title.toLocaleLowerCase()]"
```

Лямбды получают замороженные обычные данные, возвращают boolean/скаляр/кортеж скаляров. Одноразовый worker ограничивает время и не даёт доступ к DOM/страницам/привилегированным API. Регулярные выражения тоже исполняются вне UI-потока; Promise и неподходящие ключи отвергаются.

Обычная сортировка заменяет выбранные соседние позиции, сохраняя позиции остальных. `scope:"folder"` или `"subtree"` с `folderId` сортирует детей папки либо каждый уровень дерева, включая папки как единые элементы. Если передана выборка, сортируются только её элементы, даже внутри папки; пустая выборка ничего не переставляет. Явно выбранная вложенная папка переносится самостоятельно, не захватывая родительскую. Split View перемещается целиком. `order` задаёт точную перестановку выбранных ID одного уровня, `beforeId`/`afterId` — устойчивый якорь. Несколько назначений в одной операции:

```json
{"action":"move","placements":[
  {"tabIds":["<a>","<b>"],"spaceId":"<research>","folderId":"<papers>"},
  {"groupIds":["<folder-tree>"],"destinationWindowId":"<other-window>","spaceId":"<work>"}
]}
```

Открытие принимает `urls` (строки либо `{url,title,containerId}`), назначение, `select`, `lazy`, `reuse`. `select:false` сохраняет фокус и текущий Space, `lazy:true` откладывает загрузку, `reuse:"url"` переиспользует подходящую вкладку в целевом Space и контейнере; по умолчанию reuse выключен. Порядок новых вкладок соответствует массиву URL, в том числе в неактивном Space. Перенос между окнами сохраняет опустевшее окно, чтобы Undo мог восстановить исходное размещение.

Закрытие сначала асинхронно проверяет native beforeunload без модального диалога. Страница, требующая подтверждения, остаётся открытой с исходом `blocked` и кодом `beforeunload_confirmation`; зависшая проверка и изменение вкладки во время проверки также блокируют её закрытие. Проверка не принимает подтверждение за пользователя. Исходы blocked/pending/failed видны отдельно для каждой вкладки. Собственные SessionStore-снимки восстанавливают пакет независимо от глобального лимита недавно закрытых вкладок через `zen_tabs_undo({operationId})` либо план `reopen`. `reopen` также принимает массив `closedIds` из обычного списка недавно закрытых вкладок; он взаимоисключающий с `operationId`. Снимки только в памяти, принадлежат клиенту и действуют тридцать минут. На клиента сохраняется до 32 операций, а общий объём SessionStore-снимков ограничен 32 MiB; достижение лимита возвращает `receipt_limit` либо `recovery_limit` для объёма снимков. Перезапуск сервера или `zen_client_disconnect` удаляет историю клиента. Отключайтесь только после завершения нужных Undo/восстановлений; заново инициализированное подключение использует тот же сохранённый доступ. Undo отказывается молча перезаписывать последующие изменения.

## Закрепления

`zen_pins` использует общую выборку. `list` показывает сохранённый/текущий URL, пользовательское название и `pinChanged`. `reset` возвращает сохранённый адрес, `replace` делает текущий адрес сохранённым, `setUrl` задаёт адрес явно, `rename` меняет название, `unload` выгружает страницу. Изменения возвращают Undo. normal/pinned/essential меняются через пакетный план `pin` с `mode`.

## Медиа и PiP

`zen_media_items` перечисляет конкретные аудио/видео загруженных вкладок и фреймов. `mediaId` привязан к клиенту/фрейму/документу. `zen_media_control` принимает `mediaIds` либо общую выборку: play/pause/stop/mute/unmute; `volume` с `volume:0..1`; `rate` с `playbackRate:0.0625..16`; `seek` с `offsetSeconds:-30` либо `positionSeconds:120`; `pauseOthers`/`duckOthers` с `exceptMediaIds`/`exceptTabIds`; `restore` с собственным `operationId`, если затронутое состояние с тех пор не изменилось.

`zen_pip_windows` возвращает настоящие окна проигрывателей, исходные видео и мониторы из нативного `nsIScreenManager.screens`. ID монитора относится к текущему экземпляру/топологии, это не постоянный аппаратный ID. Геометрия в desktop pixels допускает отрицательные координаты и учитывает масштаб экранов.

`zen_pip` открывает `mediaId`, закрывает/управляет `playerId`. `action:"place"` принимает `monitorId`, `topologyRevision`, `corner`, `margin`, `width`/`height` или `x`/`y`. Размеры задают ограничивающий прямоугольник с сохранением пропорций; размещение ограничивается рабочей областью. Ответ содержит запрошенную и наблюдаемую геометрию, `constrained` отмечает ограничения ОС. После изменения экранов заново перечислите мониторы.

## Подборки и правила

`zen_sidebar_views`: list/save/delete/query/reorder. `definition` содержит `name`, `filter`, необязательные `filterLambda`, `enabled`. Подборки появляются в сайдбаре с живым счётчиком; раскрытие показывает существующие вкладки, клик выбирает вкладку. Их исходное размещение сохраняется. UI показывает страницы по 100 совпадений с кнопками перехода; MCP предоставляет полную пагинацию.

`zen_sidebar_rules`: list/save/delete/preview/run/undo/reorder. Определение дополняется `operation`, `automatic` (по умолчанию `false`), `events`. Сохраняются долговечные условия и ID Spaces/папок; временные ID вкладок/окон/планов/выборок запрещены. Файл профиля `zen-mcp-workspace.json` не содержит SessionStore-снимков.

Автоматические события: TabOpen, LocationChange, TabAttrModified, TabPinned, TabUnpinned, MediaPlaybackChange (по умолчанию первые два). Правила используют общую очередь мутаций и первый подходящий enabled-rule; собственные эффекты не запускают цикл. Разрешены move/sort/pin/discard. close/open доступны вручную. Последние автоматические действия/ошибки видны через list; undo использует их operationId. Автоматизация действует при включённом MCP.

`zen_native_routes` даёт list/save/delete существующей маршрутизации ссылок. `zen_live_folders` перечисляет RSS/GitHub-провайдеры и запускает refresh. Коллекции отображают существующие вкладки; live folders получают новые данные из источников.

## Экспериментальный WebMCP

`zen_site_tools` с `action:"status"` сообщает возможности фактического движка. `zen_site_tools_configure({enabled:true})` явно включает `dom.modelcontext.enabled`; страницу после этого нужно перезагрузить. Тестовая настройка не включается. Версия Firefox использует `navigator.modelContext.registerTool`, а не более поздний `document.modelContext`.

`zen_site_tools` с `action:"list"`, `tabId`, `documentId` и необязательным `frameId` получает список через нативный `nsIModelContextService`. `zen_site_tool_call` требует ту же цель, origin, listId, toolName, schemaDigest и input. Список принадлежит клиенту, действует 30 секунд и повторно проверяется перед вызовом. Доступны обычные HTTP(S) документы; регистрацию текущий движок поддерживает в верхнем документе.

Схемы/аргументы ограничены по размеру и глубине, проверяется поддерживаемое подмножество JSON Schema. Неподдерживаемые конструкции доступны для осмотра, но не вызова. Описания и результаты — недоверенные данные сайта, не инструкции агенту.

Движок не поддерживает отмену уже переданного вызова и атомарное закрепление версии callback: `nativeCancellation:false`, `atomicRegistryIdentity:false`. После таймаута, смены документа или нативного отказа исход может быть неизвестным. `zen_site_tool_result({operationId})` получает поздний результат; автоматического повторного запуска нет.

## Проверка

Логические проверки находятся в `tests/mcp/`. Подписанный кандидат прошёл нативные проверки дерева/фокуса, закрытия/восстановления, worker-лямбд, отдельных видео/PiP, экрана, UI подборок, автоматических правил, синтетического WebMCP и сохранения того же тестового профиля после перезапуска. Точный SHA, 256 логических проверок, standalone-доказательство и границы приёмки записаны в [отчёте](mcp-workspace-validation.md). На физическом устройстве проверен один монитор; Linux и Windows не проверены. Кандидат не считается установленным в основной Zen до подтверждённого обновления.
