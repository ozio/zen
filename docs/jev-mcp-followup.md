# Jev Ultrafast поверх встроенного MCP Zen

Записано 9 октября 2026 года по просьбе пользователя. Это следующий возможный этап после реализации, проверки и установки пункта 9. Сейчас Jev не внедрять и не расширять ради него текущую сборку MCP. Добавить отдельную задачу в общий список после завершения пункта 9; существующие номера сохранить.

Идея: локальный плагин для Codex быстро выполняет последовательность действий в Zen через встроенный MCP, используя Jev Ultrafast для выбора операции и цели. При затруднении он передаёт обычному агенту Codex актуальное состояние и список уже исполненных действий. В браузере остаются наблюдение и исполнение; runner, модели, ключи провайдеров и управление целью находятся снаружи.

[Исходный проект Jev Ultrafast](https://github.com/browser-use/jev-ultrafast) использует таблицу наблюдаемых элементов: Jev выбирает действие и совместимую цель, а небольшая генеративная модель пишет текст для полей. Существующий исполнитель подключает Chrome через Browser Harness. Для Zen нужен адаптер к его MCP. Скорость и надёжность такого адаптера пока не измерены.

## Основа в текущем MCP

В реализации пункта 9 предусмотрены явные instance/window/tab/frame/document ID, постраничные снимки DOM, iframe и открытые shadow roots, одноразовые handles со сроком 30 секунд, нативные действия, семантические операции Zen и подписки на изменения браузера и навигацию. Действие возвращает состояние выбранного элемента и документа. Новый полный снимок после действия, DOM revision внутри SPA и очередь по отдельным целям пока не реализованы; текущая очередь сериализует все мутации экземпляра.

## Предлагаемый порядок следующей работы

1. Сделать внешний runner и адаптер к существующему MCP без изменения ядра Zen. Измерить задержку, число вызовов и успешность на синтетических и реальных страницах.
2. Если измерения покажут необходимость, добавить компактный `observe`: role/name/value/enabled, допустимые действия, frame/document, snapshot/revision и непрозрачный handle. Явно возвращать обрезку и пагинацию.
3. Рассмотреть `act_and_observe`: ровно одно действие по свежему handle, ограниченное ожидание проверяемого условия и новый компактный снимок. Не повторять действие автоматически после ошибки или таймаута.
4. Рассмотреть подписки на DOM revision для SPA и очереди по целям. Перемещение между окнами блокирует обе цели; произвольный системный JS требует блокировки экземпляра. Ожидание одного сайта не должно задерживать другую вкладку.
5. Во внешнем runner реализовать `run_goal` с лимитом шагов и времени, checkpoint и результатами `done` / `needs_fallback`. Передавать Codex текущее наблюдение, исполненные действия и операции с неизвестным исходом. После таймаута сначала проверять состояние, чтобы не выполнить клик повторно.

Отдельно проверить переключение на обычного агента, два клиента, смену документа, устаревшие элементы и работу в фоновых вкладках Gecko. Семантические команды Spaces, вкладок, папок и Split View использовать через существующие API MCP. Выбор моделей, формат плагина, условия остановки и критерии приёмки уточнить перед реализацией.
